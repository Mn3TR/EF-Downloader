# 取证样本

这些小文件是调查过程中从官方 CDN 实际下载的原始样本，保留下来是因为
`docs/REPORT.md` 里的关键结论依赖它们。**不要删除。**

## `dl_main_A557940E...chk` 与 `dl_main_C81609E1...chk`

两个 **40 字节**的样本，来自通道 A 的分卷包。

它们的**内容 md5 相同**（`e1d41e1e7eb7b24939ff29cc4c350602`），
但**文件名不同**：

```
A557940E5BE48FE54507370E4CE451E3.chk
C81609E1D919399363313B5C5C607E2F.chk
```

这一条推翻了「文件名 = 内容哈希」的假设，并确立了整套方案的可行性：

- **文件名是稳定的逻辑身份**
- **清单里的 `md5` 字段是内容版本**

两者独立。因此「同一个逻辑资源、内容变了」表现为**同名不同 md5**，
而「不同逻辑资源、内容碰巧一样」表现为**不同名同 md5**。

**直接后果：原地覆盖永远是安全的。** 不需要先删后写，不需要额外空间做替换，
也不需要为「重命名」做特殊处理。

## `dl_initial_*.chk`

通道 B（资源热更新）的样本，用于验证热更新清单里的 `.chk`
从 CDN 取回后与清单记录逐字节一致（不需要解密或二次解包）。

## `dl_42A8FCA6.blc`

通道 B 的 bundle 索引文件。前 4 字节是 `03 00 00 00`，即 `protocol = 3`，
与公开的逆向资料一致。

---

这些文件的体积都很小（合计不到 100 KB），但它们是结论的**证据**，
而不是可重新生成的中间产物——CDN 上的对应 URL 随时可能失效。
